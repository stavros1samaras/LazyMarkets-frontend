# LazyMarkets - Project Guidelines & Rules

Welcome to **LazyMarkets** (`frontend-next`), a Next.js web application for financial market analysis (Fundamental, Technical, Sentiment, and Global Economic data).

---

## 🛠️ Tech Stack & Dependencies

- **Framework**: [Next.js](https://nextjs.org/) (App Router), React 19, TypeScript
- **Styling**: Tailwind CSS v4, CSS Variables, `next-themes` (Dark/Light mode support)
- **UI Components & Icons**: [shadcn/ui](https://ui.shadcn.com/) (New York style), [Lucide React](https://lucide.dev/), [Sonner](https://sonner.emilkowal.ski/) (toasts)
- **Charts & Data**: [Recharts](https://recharts.org/), [SheetJS (xlsx)](https://sheetjs.com/)
- **Forms & Validation**: `react-hook-form`

---

## 📐 Development Guidelines & Rules

### 1. Component & React Conventions

- **Server vs. Client Components**: By default, keep components as Server Components. Add `"use client"` only when components need state (`useState`, `useEffect`), custom hooks, event listeners, or browser APIs.
- **Path Aliases**: Always use the configured TypeScript path alias `@/*` (resolves to `./src/*` per `tsconfig.json`). Import directly from the target module/file, e.g.:
  - `@/components/*`
  - `@/lib/*`
  - `@/contexts/*`
  - `@/_features/*`

### 2. shadcn/ui & Styling Rules

- **Base Components Integrity**: **Never** modify source code inside `src/components/ui/` directly.
- **Custom Styling**: Always customize appearance via the `className` prop at the call site using Tailwind CSS utility classes and `cn()`.
- **Theme Awareness**: Ensure all UI elements look crisp and legible in both light and dark modes using Tailwind semantic color tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`, etc.).
- **Use `Span` / `Div` when you can**: Prefer the `Span` and `Div` element primitives (`src/components/elements/`) over raw `<span>` / `<div>` tags. `Span` is `inline-flex`, `Div` is `flex` — use them whenever their default layout fits.

### 3. TypeScript & Code Quality

- **Strict Typing**: Avoid `any`. Define clear interfaces or types for API responses, props, and financial data structures.
- **Modular Code**: Place domain/feature-specific components and helper hooks in `src/_features/<feature>/` rather than polluting top-level folders.
- **Error Handling**: Implement graceful error boundaries and fallback states (using Next.js `error.tsx` / `loading.tsx` or inline skeletons) for asynchronous data fetches.

### 4. Bundling & Imports

- **No barrel files**: DO NOT create broad `index.ts` re-exports (e.g. `components/index.ts`) that re-export many modules — they cause bundle bloat and obscure real import paths. Import directly from the target module/file.

### 5. UI Composition

- **Compose, don't prop-drill**: For complex UI, prefer compound components that share state via a small context (Provider / Frame / Header / Footer) over boolean prop proliferation (`isEditing`, `showDetails`). See the `vercel-composition-patterns` skill for the full pattern library.

### 6. Quality & Verification

- **Verify before done**: New or refactored UI should be checked for **performance** (bundle size, no waterfalls, parallelize with `Promise.all`), **responsive design** (mobile → desktop), **SEO** (metadata, semantic HTML, heading order), **security** (no leaked secrets, correct Server/Client boundaries), and **accessibility** (semantic markup, ARIA, keyboard navigation, color contrast). The Frontend Engineer agent applies these gates automatically.

### 7. Skills & Standards Are Mandatory (No Tech Debt)

- **Load skills before coding**: Before creating or refactoring any component, page, or UI, the agent **MUST** read the relevant installed skills (`.agents/skills/*/SKILL.md`) — at minimum `tailwind`, `typescript`, `responsive-design`, `vercel-composition-patterns`, and `vercel-react-best-practices` — and apply them. This is a hard gate, not optional.
- **Responsive by default**: Every new/refactored component must be mobile-first and verified across breakpoints (`sm`, `md`, `lg`, `xl`). No component is "done" until it renders correctly on mobile and desktop.
- **Semantic HTML**: Use correct semantic elements and heading order (one `h1` per page, `h2`→`h6` in sequence). No div-soup.
- **Tailwind conventions**: Follow the class-ordering and token rules in the `tailwind` skill (semantic tokens only, `cn()` for merged classes, responsive variants adjacent to their base utility).
- **No shortcuts**: Do not ship a first-pass component that ignores these standards and "fix it later." Standards apply from the first version.

- **`.github/prompts/`** — reusable prompt templates (slash commands):
  - `audit-agent-files` — audits these customization files for clarity + compliance.
- **`.github/cheatsheet.md`** — human reference for built-in Copilot slash commands / participants (not loaded as an agent; intentionally excluded from the audit).
